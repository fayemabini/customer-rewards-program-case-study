# Retrospective

## What worked

- Starting from observed customer behavior gave the project a clear business problem.
- Defining rules before technical setup reduced avoidable rework.
- Separating business approval from execution made decision ownership clear.
- QA included refunds, duplicate actions, and abuse scenarios rather than only the happy path.

## What could improve

- Validate reward economics earlier.
- Include customer support earlier in program design.
- Establish analytics requirements before build begins.
- Add a small pilot / soft launch when feasible.

## Next-iteration recommendations

- Review redemption thresholds
- Review high-performing earn actions
- Remove actions that create abuse or low-value engagement
- Improve program visibility where adoption is low
- Test bonus-point campaigns selectively
