# Points & Rewards Program | Product/Program Management Case Study

> Portfolio case study based on a real type of program I have managed. Specific company data, names, and confidential details are intentionally omitted.

## Overview

This case study shows how I would structure and manage a customer points and rewards program from insight to launch.

The program started with a recurring customer behavior: users frequently asked for discounts. Rather than treating discounting as a one-off request, the opportunity was to turn that behavior into a structured loyalty mechanism.

The idea: allow users to earn points through selected website and learning activities, then redeem those points for rewards or discounts.

## Business problem

Customers wanted more ways to save.

Repeated discounting can reduce perceived value and create inconsistent customer experiences. The opportunity was to offer customers a way to earn value through actions that also support engagement, retention, and repeat purchases.

## Product hypothesis

If customers can earn points by completing valuable actions, then discount demand can be redirected into repeat engagement and loyalty.

Examples of earn actions may include:

- Completing a purchase
- Completing a course or learning milestone
- Participating in selected website activities
- Reviews or feedback
- Promotional engagement

Actual rules depend on business approval, platform capabilities, and abuse-prevention requirements.

## My role

As Project Manager / Program Lead, I would own:

- Understanding the business problem and user behavior
- Preparing the proposal and business case
- Coordinating stakeholder approval
- Defining program requirements and rules
- Breaking the program into workstreams
- Identifying owners, dependencies, risks, and resources
- Coordinating website / platform setup
- Managing QA and launch readiness
- Coordinating customer communication
- Tracking post-launch performance and recommending improvements

## Delivery approach

I would manage the program using two views:

### Timeline / Roadmap
Used for the overall program:
**Discovery → Proposal → Approval → Design → Build → QA → Launch → Optimization**

### Kanban Board
Used for day-to-day execution:
**Backlog → In Progress → Review / QA → Done**
